F. Authentication/session stability
- Version 1.6.10 fixed the infinite startup screen: “Restoring your secure session…” no longer blocks forever.
- Windows Credential Manager operations were moved away from the UI thread and protected with timeouts.
- Large Supabase sessions are stored in safe chunks because Windows Credential Manager has a small credential-blob limit.
- Version 1.6.11 fixed the later error: “Secure session restoration failed” / “Secure session storage is incomplete.”
- Root cause found by real Windows testing: an expired Supabase session triggered deletion; chunks were deleted before the root manifest. If root deletion failed, a dangling manifest pointed to missing chunks.
- Fix in commit 3566a33:
  - delete the public/root manifest before deleting chunks,
  - self-heal any legacy incomplete chunked session to a clean signed-out state,
  - run native get/set/delete work outside the UI thread,
  - retry safe session reads/restoration,
  - normalize rejected string/error-like failures,
  - treat truly terminal refresh rejection as signed-out instead of a scary generic error.
